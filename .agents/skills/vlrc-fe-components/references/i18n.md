# Internationalization (i18n), RTL & Multi-Calendar Reference

`@vlrc-fe/components` leverages the native internationalization system from Meta's Astryx design system (`@astryxdesign/core/i18n`), providing automatic component string localization, text direction tracking (RTL), and multi-calendar date systems.

---

## 1. Setup & `<InternationalizationProvider>`

Wrap your application or subtree with `<InternationalizationProvider>`:

```tsx
import { InternationalizationProvider } from '@vlrc-fe/components';

export function App() {
  return (
    <InternationalizationProvider locale="vi">
      <YourAppContent />
    </InternationalizationProvider>
  );
}
```

If no provider is present, all Astryx and VLRC components fall back gracefully to standard English strings.

---

## 2. Coexistence with `react-i18next`

Astryx i18n is designed to coexist seamlessly with `react-i18next` and the repository's `i18n-flat-key-management` skill. The two libraries share the active locale state while owning their respective catalogs:

```tsx
import { InternationalizationProvider } from '@vlrc-fe/components';
import { useTranslation } from 'react-i18next';

export function LocalizedApp() {
  const { i18n } = useTranslation();

  return (
    <InternationalizationProvider locale={i18n.language}>
      {/* Astryx localizes its internal component strings (DatePickers, Pagination, FileUpload) */}
      {/* react-i18next localizes product application strings */}
      <Dashboard />
    </InternationalizationProvider>
  );
}
```

## 3. Available Hooks

Exported from `@vlrc-fe/components` and `@vlrc-fe/components/i18n`:

### `useLocale()`

Reads the active locale string:

```tsx
import { useLocale } from '@vlrc-fe/components';

const locale = useLocale(); // e.g. "vi-VN", "en-US"
```

### `useDirection()`

Reads the current text direction (`'ltr'` or `'rtl'`), automatically derived from the locale:

```tsx
import { useDirection } from '@vlrc-fe/components';

const direction = useDirection(); // "ltr" | "rtl"
```

> [!TIP]
> Prefer CSS logical properties (`margin-inline`, `padding-inline`, `inset-inline`) over manual conditional styles wherever possible.

### `useCollator(options?)`

Returns a memoized, locale-aware string comparator for accurate sorting in data tables:

```tsx
import { useCollator } from '@vlrc-fe/components';

const collator = useCollator({ sensitivity: 'base' });
const sorted = items.sort((a, b) => collator.compare(a.name, b.name));
```

### `useTranslator()`

Resolves translation keys against the active catalog:

```tsx
import { useTranslator } from '@vlrc-fe/components';

const t = useTranslator();
const searchLabel = t('@astryx.search.placeholder');
```

## 4. Multi-Calendar Date Systems

Astryx's `DatePicker`, `Calendar`, and date controls support multiple calendar systems while maintaining standard Gregorian ISO dates (`YYYY-MM-DD`) in underlying values:

- **Supported Calendars**: Gregorian, Persian (`persian`), Hebrew (`hebrew`), Hijri (`islamic-umalqura`), Buddhist (`buddhist`), Japanese (`japanese`), Chinese (`chinese`).
- **Usage**:
  ```tsx
  <InternationalizationProvider locale="fa-IR" calendar="persian">
    <DatePicker value={isoDate} onChange={setIsoDate} />
  </InternationalizationProvider>
  ```

## 5. Development Pseudo-Locale Testing

To catch untranslated strings, hardcoded English text, or UI layout overflow caused by expanded translations, test with the `pseudo` locale:

```tsx
<InternationalizationProvider locale="pseudo">
  <App />
</InternationalizationProvider>
```

In `pseudo` mode, every localized string is enclosed in `⟦...⟧` with accented characters (e.g. `⟦Sëärċh...⟧`), instantly highlighting any non-localized strings in the UI.
